# Task 4 — API Specification

> Status: **partially implemented 2026-09-19.** The OpenAPI document is
> generated by FastAPI from the Pydantic models; this document fixes the
> contract those models must produce.
>
> **Built:** `/health`, `/ready`, `/meta/disclaimer`, `/auth/register`,
> `/auth/login`, `/auth/me`, and the `/projects` collection. The RFC 9457
> error contract, bearer authentication and ownership isolation are in place.
>
> **Not built yet:** upload, extract, lines, classify, classifications,
> questions, business-activities, finalize, statement, impact, export, rules,
> accounts, audit-logs, jobs.

## 1. Conventions

- Base path `/api`. Versioned via `Accept: application/vnd.ifrs18.v1+json`;
  unversioned requests get v1.
- Auth: `Authorization: Bearer <JWT>`. Every project-scoped route enforces
  ownership at the repository layer — an id belonging to another user returns
  `404`, never `403`, so ids cannot be probed.
- `snake_case` JSON. Timestamps RFC 3339 UTC.
- **Monetary values are JSON strings**, not numbers: `"amount": "-70000.000000"`.
  IEEE-754 doubles cannot round-trip `numeric(38,6)`, and silent precision loss
  in a reconciliation tool is unacceptable. The frontend parses with a decimal
  library and, per arch §3, only formats — never computes.
- Long-running operations return `202 Accepted` with a `job` object; clients poll
  `GET /api/jobs/{job_id}` or the project's `status`.
- Errors use RFC 9457 `application/problem+json`:
  ```json
  { "type": "https://ifrs18.app/errors/reconciliation-failed",
    "title": "IFRS 18 reconstruction could not be reconciled.",
    "status": 409, "detail": "PBT differs by 1,000,000",
    "instance": "/api/projects/…/finalize",
    "checks": [ … ] }
  ```
- Idempotency: `POST` routes that create work accept `Idempotency-Key`.

## 2. Endpoints

### Projects

#### `POST /api/projects`
```json
{ "name": "삼성전자 2025 연결",
  "company": { "name": "삼성전자", "identifier": "1248100998",
               "identifier_scheme": "KR_BRN", "jurisdiction": "KR" },
  "fiscal_year": 2025,
  "period_start": "2025-01-01", "period_end": "2025-12-31",
  "basis": "CONSOLIDATED",
  "presentation_currency": "KRW",
  "presentation_scale": 6 }
```
→ `201` with the project object. `status: "DRAFT"`.

#### `GET /api/projects/{project_id}`
Returns the project plus a `progress` block that drives the UI without extra
round-trips:
```json
{ "id": "…", "status": "IN_REVIEW",
  "reconciliation_status": "NOT_RUN",
  "rule_set_version": "2026.09.1",
  "progress": {
    "lines_total": 84, "lines_classified": 84,
    "requires_review": 7, "reviewed": 3,
    "open_questions": 1,
    "can_finalize": false,
    "blocking_reasons": [
      { "code": "OPEN_REVIEW_QUESTION", "count": 1 },
      { "code": "UNREVIEWED_CLASSIFICATION", "count": 4 } ] } }
```
`can_finalize` is computed server-side. The client must not re-derive it.

#### `GET /api/projects` — list, paginated (`?limit=&cursor=&status=`).
#### `DELETE /api/projects/{project_id}` — soft delete; purges uploads per §32.

### Upload and extraction

#### `POST /api/projects/{project_id}/upload`
`multipart/form-data`, field `file`. Enforced before anything else:
allow-list by sniffed content type (`xlsx`, `xls`, `csv`, `pdf`), size limit from
config, SHA-256 computed, malware scan hook.

→ `201`
```json
{ "id": "…", "original_filename": "fs.xlsx", "mime_type": "…",
  "size_bytes": 184320, "sha256": "…",
  "scan_status": "CLEAN", "parse_status": "PENDING" }
```
Rejections: `413` size, `415` type, `422` unreadable, `409` infected.

#### `POST /api/projects/{project_id}/extract`
```json
{ "uploaded_file_id": "…",
  "hints": { "sheet": "손익계산서", "header_row": 4, "amount_columns": ["D"] } }
```
→ `202` `{ "job": { "id": "…", "status": "RUNNING" } }`

On completion the project reaches `EXTRACTED` and exposes:

#### `GET /api/projects/{project_id}/statements`
#### `GET /api/projects/{project_id}/lines`
```json
{ "items": [
  { "id": "…", "ordinal": 12, "depth": 1,
    "raw_label": "이자수익", "raw_value": "3,000",
    "amount": "3000.000000", "is_subtotal": false,
    "normalized_account": { "code": "INTEREST_INCOME", "label_ko": "이자수익" },
    "normalization_method": "SYNONYM", "normalization_score": "1.0000",
    "current_category": "OTHER_INCOME",
    "source_locator": { "sheet": "손익계산서", "row": 17, "column": "D", "cell": "D17" } } ],
  "extraction_checks": [
    { "check": "GROSS_PROFIT", "reported": "30000.000000",
      "computed": "30000.000000", "delta": "0.000000", "passed": true },
    { "check": "PROFIT_BEFORE_TAX", "reported": "12000.000000",
      "computed": "12000.000000", "delta": "0.000000", "passed": true } ] }
```
`extraction_checks` implements spec §17: the extracted detail lines are summed
and compared against the subtotals printed in the source, *before* any IFRS 18
work begins. Extraction that does not reproduce the source's own subtotals is
reported as failed rather than passed downstream.

#### `PATCH /api/lines/{line_id}`
Manual correction of extraction (amount, label, `is_subtotal`,
normalized account). Writes an audit log entry; invalidates classifications.

### Business activities and questions

#### `GET /api/projects/{project_id}/business-activities`
#### `PUT /api/projects/{project_id}/business-activities/{activity_type}`
```json
{ "is_main_business_activity": true,
  "description": "고객에 대한 금융 제공이 주된 영업활동",
  "source": "USER" }
```
Only a user may set `confirmed_by_user: true` (spec §10). An AI suggestion may
create the row with `source: "AI_SUGGESTED"` and `is_main_business_activity:
null`, which does **not** unblock any rule.

#### `GET /api/projects/{project_id}/questions`
```json
{ "items": [
  { "id": "…", "question_key": "SMBA_INVESTING_IN_ASSETS",
    "question_text_ko": "이 회사에서 금융자산에 대한 투자가 주요 사업활동입니까?",
    "question_text_en": "Is investing in financial assets a main business activity of this entity?",
    "raised_by_rule_id": "IFRS18-SMBA-001",
    "options": ["YES", "NO", "NOT_SURE"],
    "affected_line_count": 4,
    "affected_amount": "83000000000.000000",
    "answer": null, "blocks_finalization": true } ] }
```
`affected_amount` tells the user what turns on their answer before they give it.

#### `POST /api/questions/{question_id}/answer`
```json
{ "answer": "YES", "note": "2025 사업보고서 II-1 참조" }
```
→ `200`; re-runs the affected rules only. `NOT_SURE` is accepted and stored, but
leaves the question blocking with `blocking_reason: "ANSWER_NOT_SURE"`.

### Classification

#### `POST /api/projects/{project_id}/classify`
```json
{ "mode": "FULL",            // FULL | UNRESOLVED_ONLY
  "use_ai_assistant": true,
  "preserve_user_overrides": true }
```
→ `202` job. `preserve_user_overrides: true` (default) guarantees re-running
classification never silently discards a human decision.

#### `GET /api/projects/{project_id}/classifications`
`?requires_review=true&category=&method=&sort=impact_abs_desc&limit=&cursor=`

Default sort is `impact_abs_desc` — largest absolute effect on operating profit
first (arch §9).

```json
{ "items": [
  { "id": "…", "line_id": "…",
    "original_account": "이자수익",
    "normalized_account_code": "INTEREST_INCOME",
    "amount": "3000.000000",
    "current_category": "OTHER_INCOME",
    "proposed_ifrs18_category": "INVESTING",
    "proposed_ifrs18_subcategory": "INVESTING_INCOME",
    "final_ifrs18_category": "INVESTING",
    "classification_method": "RULE",
    "rule_id": "IFRS18-INVESTING-001",
    "rule_source_reference": "IFRS 18 paragraph 49",
    "ai_confidence": null,
    "confidence_band": "HIGH",
    "requires_human_review": false,
    "user_override": false,
    "impact_on_operating_profit": "-3000.000000",
    "evidence": [ { "evidence_type": "RULE_SOURCE", "reference": "IFRS 18 paragraph 49",
                    "produced_by": "RULE" } ] } ],
  "summary": { "total": 84, "by_method": { "RULE": 61, "RESIDUAL_DEFAULT": 16,
               "AI": 6, "USER": 1, "UNRESOLVED": 0 },
               "requires_review": 7 } }
```

#### `GET /api/classifications/{classification_id}`
Full detail for the row-click drill-down (§7): the rule's full text and citation,
the AI's verbatim reasoning and raw response, all evidence, the review history,
and the source locator back to the originating cell or PDF region.

#### `PATCH /api/classifications/{classification_id}`
```json
{ "final_ifrs18_category": "OPERATING",
  "final_ifrs18_subcategory": "OPERATING_REVENUE",
  "override_reason": "당사의 주요 사업활동에 해당",
  "action": "OVERRIDDEN" }
```
→ `200`. Sets `user_override: true`, `classification_method: "USER"`, writes a
`user_reviews` row and an `audit_logs` row, and recomputes impact. Accepting an
existing proposal unchanged is `action: "ACCEPTED"` — also recorded, because
"a human looked at this and agreed" is itself audit-relevant information.

Bulk form: `PATCH /api/projects/{project_id}/classifications` with an `items`
array, applied in one transaction.

### Finalize, statement, impact

#### `POST /api/projects/{project_id}/finalize`
Runs reconstruction + all validations.

→ `200` when reconciled:
```json
{ "status": "FINALIZED", "reconciliation_status": "PASSED",
  "impact_analysis_id": "…", "finalized_at": "2026-09-19T…Z" }
```
→ `409 problem+json` when not:
```json
{ "type": "https://ifrs18.app/errors/reconciliation-failed",
  "title": "IFRS 18 reconstruction could not be reconciled.",
  "status": 409,
  "checks": [ { "check": "PROFIT_BEFORE_TAX", "expected": "12000.000000",
                "actual": "11000.000000", "delta": "-1000.000000",
                "tolerance": "1.000000", "passed": false } ] }
```
→ `422` when blocked by unanswered questions or unreviewed items, listing them.

#### `GET /api/projects/{project_id}/statement`
`?view=ifrs18|reported|comparative`
```json
{ "reconciliation_status": "PASSED",
  "currency": "KRW", "scale": 6,
  "sections": [
    { "category": "OPERATING", "label_en": "Operating", "label_ko": "영업",
      "lines": [ { "label_ko": "매출액", "amount": "100000.000000", "line_id": "…" },
                 { "label_ko": "영업비용", "amount": "-90000.000000", "line_id": "…" } ],
      "subtotal": { "key": "OPERATING_PROFIT", "label_en": "Operating profit",
                    "amount": "10000.000000" } },
    { "category": "INVESTING", "…": "…" } ],
  "subtotals": [
    { "key": "OPERATING_PROFIT", "amount": "10000.000000" },
    { "key": "PROFIT_BEFORE_FINANCING_AND_INCOME_TAXES", "amount": "13000.000000",
      "presented": true },
    { "key": "PROFIT_BEFORE_TAX", "amount": "11000.000000" },
    { "key": "PROFIT_FOR_THE_PERIOD", "amount": "…" } ],
  "disclaimer": "This analysis is an IFRS 18 classification and impact analysis tool. It does not constitute accounting advice or an authoritative determination of IFRS compliance." }
```
The disclaimer (spec §24) is returned by the API, not hardcoded in the frontend,
so it cannot be lost in a UI refactor and is present in every export.

`presented` on a subtotal is a flag rather than an omission — see
`06-open-accounting-questions.md` Q3 regarding entities for which the
"profit before financing and income taxes" subtotal is not required.

presentation without changing profit.

Every waterfall step carries `classification_ids`, which is what makes the
click-through in spec §5 and §23 a simple navigation rather than a re-query.

### Export

#### `POST /api/projects/{project_id}/export` `{ "format": "XLSX" }` → `202` job
#### `GET /api/projects/{project_id}/export/excel`
#### `GET /api/projects/{project_id}/export/pdf`
Return `303` to a short-lived signed URL, or `200` with the bytes for small
files. Both are refused with `409` unless
`reconciliation_status == "PASSED"`, **unless** the caller passes
`?acknowledge_unreconciled=true`, in which case the produced file is watermarked
"UNRECONCILED — DO NOT RELY ON" on every page/sheet. This satisfies §19 while
still letting a user take failing output away to investigate it.

### Supporting

- `GET /api/jobs/{job_id}` — `{ status, progress, error }`
- `GET /api/rules` — the active rule set with citations (feeds the
  "why?" panel and lets a reviewer audit the engine itself)
- `GET /api/accounts` — normalized account dictionary
- `GET /api/projects/{project_id}/audit-logs` — paginated audit trail
- `GET /api/config/classification` — active confidence thresholds and tolerances

## 3. Deviations from spec §15, and why

Spec §15 lists a minimum set; all of those exist above. Four additions were
necessary:

1. **`/questions` + `/business-activities`** — spec §5 and §10 require a
   user-facing question step and a confirmed-activity entity, but §15 had no
   endpoint for either. Without these the `NEEDS_FACT` path has no API surface.
2. **`/lines` + `PATCH /lines/{id}`** — extraction must be reviewable and
   correctable before classification; otherwise a mis-read cell can only be fixed
   by re-uploading.
3. **`/jobs/{id}`** — extraction and classification are too slow for a
   synchronous request on a real statement.
4. **`/rules`** — explainability (§23) requires the user to be able to read the
   rule that decided their number, with its citation.

`POST /api/projects/{id}/export` was added alongside the two `GET` export routes
in §15 so that generation can be asynchronous; the `GET` routes remain as
specified and serve the generated file.
